# prodloop V0.6 上下文预算与持久记忆验证报告

验证日期：2026-09-04

## 本次目标

降低长周期自主开发对不断增长的对话上下文的依赖，让 Agent 在压缩、暂停或更换会话后能从项目证据恢复，同时避免把摘要误当成产品合同或事实来源。

## 实现范围

- 默认软上下文上限为 120K tokens，建议在可信用量达到 80% 时检查点。
- 无 token 用量时，按每 8 个实质动作、门禁、切片、长输出和会话交接触发。
- 新增 `CONTEXT.md`，保存不超过 12000 字符的当前工作集。
- 新增 `CONTEXT_HISTORY.md`，保存检查点编号、时间、原因、阶段、代码版本和摘要大小。
- 新增 `MEMORY_CANDIDATES.md`，只保存有证据的跨项目候选经验，不自动写入外部长记忆。
- 新增 `checkpoint_context.py`，验证摘要结构、大小及其精确下一步与 `STATE.json.next_action` 一致。
- 新增 `track_context_budget.py`，持久记录实质动作，并结合可信的 context K 值给出检查点到期原因。
- 新增 `enable_context_management.py`，为 V1-V4 项目保留备份并非破坏性补齐上下文管理。
- 状态 schema 升级为 V5，记录检查点数量和最后检查点时间。
- 明确运行时分流：Codex 在预计自动压缩前建立检查点；Kimi Code 在检查点验证成功后按需执行 `/compact`。
- 检查点记录运行时和选定压缩路径；该记录本身不作为压缩已经发生的证据。

## 记忆边界

对话是可丢弃工作区，`CONTEXT.md` 是当前工作集，产品合同、状态、决策、测试、证据和 Git 历史才是项目权威源。摘要冲突时必须回到权威源修复。

本版本不默认引入向量库、知识图谱或跨项目自动记忆。候选经验必须具备来源、适用范围、可信度、Owner 和复核日期；向外部系统提升需要用户明确授权、权限边界、版本和过期治理。

## 证据边界

- 测试证明检查点文件和状态约束可执行，不证明宿主已经减少当前会话 token。
- `120K/96K` 是 prodloop 的检查点准备阈值，不是 Codex 内部自动压缩阈值；本次未核验或声明 Codex 的内部阈值。
- Codex 自动压缩和 Kimi Code `/compact` 是本次按用户提供的运行时事实适配；检查点历史中的路径字段记录预定机制，实际发生仍需宿主证据。
- Agent 未必能读取准确 token 用量，因此事件触发器是必须保留的后备机制。
- 摘要质量仍涉及判断，结构校验不能证明没有遗漏；关键事实必须继续保存在权威产物中。
- 外部长记忆会增加权限、过期、错误注入和治理成本，应由实际检索失败和跨项目复用需求驱动。
